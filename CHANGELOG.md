## 0.4.0 - 2026-10-11

### Changed: the compare-runs decision rule

- `compare-runs` decides with a confidence interval instead of a CV cut followed by a fixed threshold on the difference of means. It computes a Welch t interval on the log ratio of means (90% two-sided by default): `FAIL` when the whole interval for the regression is at or past `--regression-percent`, `PASS` when the whole interval is below it, and `INCONCLUSIVE` when it contains the threshold. Validity checks (environments, failed requests, missing metrics, repetition count) still come first.
- Why: simulating the old rule showed a healthy benchmark (true CV 4%, no change, 5 repetitions) was `INCONCLUSIVE` about a third of the time, and with 2 repetitions a true 12% regression passed about 13% of the time. The new rule's rates are published in `docs/gate-calibration.md`, generated by `tools/gate_simulation.py` and checked in `tests/test_gate.py`.
- The CV ceiling is now optional and off by default (`--stability-cv-percent`, Action input `stability-cv-percent`). Pass `--stability-cv-percent 5` to keep the old ceiling in addition to the interval.
- At least 3 repetitions per side are required (`--min-repetitions`, default 3, was 2). 5 or more is recommended.
- New options `--confidence` and `--min-repetitions`, and matching Action inputs. New Action outputs `regression-percent-low` and `regression-percent-high`.
- The JSON report is `schema_version: inference-ci-quality-2`. It adds `confidence_interval`, `lower_is_better`, `notes`, and `thresholds.confidence` and `thresholds.min_repetitions`; `measurement_quality` adds `enough_repetitions`, and `environment_valid` no longer depends on the wording of a reason.
- A candidate better than the baseline by more than the threshold gets a note asking to check that both sides measured the same workload.
- The quickstart has five repetitions per side and a `regressed-candidate` directory that demonstrates `FAIL`.
- The Action passes its inputs to the shell through environment variables instead of interpolating them into the script.

### Fixed: compare and diagnose

- `compare` no longer crashes with `UnboundLocalError` when a baseline value is 0; a rise from 0 in a latency, or a fall to 0 in a throughput, is a failure.
- `compare` returns `INCONCLUSIVE` (exit 2) instead of `PASS` when no latency or throughput metric is present in both files, and its overall status is `WARN` (still exit 0) when any row is in the warning band.
- `compare` is deprecated: it prints a notice on stderr pointing to `compare-runs`, and will be removed in a future release.
- `diagnose`: the queue mean is aggregated across series (`sum(rate(_sum)) / sum(rate(_count))`); with two replicas at 0.2 s it reported 0.4 s. The Prometheus client now refuses a query that returns more than one series instead of adding them up.
- `diagnose`: `QUEUE_PRESSURE` requires queue evidence (waiting requests, or a mean queue time of at least 20% of TTFT p95). TTFT over its SLO with a healthy TPOT used to be enough, which flagged prefill-heavy workloads as queueing.
- `diagnose`: a new `PREFILL_PRESSURE` finding covers TTFT over its SLO with no queue evidence and prefill time at least half of TTFT p95. Prefill time and prompt length were collected before but not used.
- `diagnose` exits 1 when it reports a critical finding; `--fail-on warning|never` changes the threshold. It always exited 0 before.

### Added: gate several metrics at once

- `--metric` can be repeated (Action: a comma-separated `metric` input). Each metric is compared in full; the combined result is `FAIL` if any metric fails, `INCONCLUSIVE` if none fails but one is inconclusive, and `PASS` only if all pass. The report notes that each extra metric adds a chance of a false alarm. With one metric the report is unchanged; with several it has `metrics` and `comparisons`. The Action's job summary has one row per metric, and a new `report` output holds the JSON report path.

### Added: read benchmark tools' own output

- `compare-runs` reads the result files of `vllm bench serve --save-result` (including `--append-result` JSON Lines), NVIDIA AIPerf and GenAI-Perf, GuideLLM `benchmarks.json`, and SGLang `bench_serving`, with no conversion step. `--format auto` (the default) detects the format per file; `--format` forces one. See `docs/input-formats.md`.
- `--gpu` and `--model` record values the result files do not carry; `--guidellm-benchmark` picks one load point of a GuideLLM sweep. Matching Action inputs `format`, `gpu`, `model` and `guidellm-benchmark`.
- p99 latencies, inter-token latency (`itl_*_ms`), end-to-end latency (`e2el_*_ms`) and total token throughput, in the normalized schema and as `--metric` choices. Every latency family has mean, median, p95 and p99.
- The report shows the input format, notes when the GPU or model was not recorded or a tool does not record failed requests, and lists skipped files under `input.ignored_files`.
- `examples/vllm-bench-serve` holds results in vLLM's own format, where throughput passes and mean TTFT fails.
- Normalized results under any file name are detected, as long as no file in the directory uses one of the standard names.

### Added

- `inference-doctor --version`, and `python -m inference_doctor`.

### Fixed

- When no repeated-run files are found, the error names the accepted file patterns and lists the JSON files that were ignored. Files such as `run1.json` used to be skipped without a word.
- `compare-runs` explains `INCONCLUSIVE` accurately. A missing or non-finite metric, or a single repetition, used to be reported as "measurements exceeded the allowed stability threshold"; the stability reason now appears only when a CV was measured, and it states that CV.
- Identical repetitions, including all-zero values, have a CV of 0 instead of no CV. `--metric requests_failed` could never pass before.
- An integer `schema_version` (`1` instead of `"1"`) gets a message that says so.

### Changed

- One exit-code scheme for every command: 0 PASS, 1 FAIL, 2 INCONCLUSIVE or UNSTABLE, 3 error with no decision. Before, `compare-runs` exited 2 (the INCONCLUSIVE code) for a missing directory or a mistyped option, `compare` exited 1 for UNSTABLE and 2 for invalid input, and `diagnose` exited 1 when Prometheus could not be queried.
- An internal error now prints one line and exits 3 instead of printing a traceback and exiting 1, which a CI job read as FAIL. Set `INFERENCE_DOCTOR_DEBUG=1` for the traceback.
- CI runs ruff, the formatter check and mypy, and tests on Python 3.11 and 3.14 on Linux plus 3.14 on macOS and Windows. Actions are pinned by commit SHA, the token is read-only, and checkouts do not keep credentials. The workflow is now `.github/workflows/ci.yml`.
- The package moved to `src/` and builds with setuptools. The version is defined once, in `inference_doctor/__init__.py`; it said 0.1.0 while the package metadata said 0.3.0.

## 0.3.0 - 2026-09-14

### Added

- Reusable GitHub Action for repeated-run inference regression gating.
- No-GPU quickstart fixtures for trying `compare-runs` locally in minutes.
- GitHub Actions documentation and PR smoke coverage.
- Measurement-quality gate with first-class `PASS`, `FAIL`, and `INCONCLUSIVE` outcomes.
- Repeated-run statistics including mean, median, sample standard deviation, CV, min/max, and descriptive outlier flags.
- Optional environment telemetry helpers for benchmark investigations.
- Experimental `inference-doctor compare` upgrade guard for normalized benchmark result files, with configurable regression thresholds, terminal and JSON output, and CI exit codes.
- Auditable historical regression and benchmark-reliability experiments that informed the measurement-quality design.

### Changed

- Repositioned the project around trustworthy inference performance CI: measurement quality is checked before a merge decision is made.
- `compare-runs` is now the primary documented workflow; Prometheus diagnosis remains supported as a secondary feature.
- Apparent outliers remain included in official decisions rather than being silently removed.
